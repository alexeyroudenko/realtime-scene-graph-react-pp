# Описание алгоритма

Этот документ описывает, как в приложении работает **генерация графа сцены (Scene Graph Generation, SGG)**: от кадра с камеры до bounding box’ов, триплетов отношений и направленного графа `networkx`.

> **English version:** [DESCRIPTION.md](DESCRIPTION.md)

## Главная идея

Проект **не** использует классический двухэтапный пайплайн (сначала детектор объектов, потом отдельная модель отношений на каждую пару). Модель **REACT++** ([maelic/REACTPlusPlus_PSG](https://huggingface.co/maelic/REACTPlusPlus_PSG)) делает **один end-to-end проход** и сразу возвращает и детекции объектов, и связи между ними.

Порядок «сначала фильтруем связи, потом боксы» в коде постобработки — это **политика отображения и фильтрации**, а не порядок работы нейросети.

## Пайплайн

```
Кадр с камеры (BGR)
    → letterbox-препроцессинг (640×640)
    → REACT++ ONNX inference (один проход)
    → боксы (N×6) + связи (M×5)
    → пороги и перенумерация индексов
    → SceneGraphResult (объекты, связи, networkx DiGraph)
    → визуализация OpenCV
```

Реализация: `src/inference/scene_graph.py`, `src/inference/model_loader.py`.

## 1. Препроцессинг

Каждый кадр масштабируется с **letterbox** до `640×640` (`INPUT_SIZE` в `src/config.py`):

- Сохраняются пропорции; пустые области заполняются серым `(114, 114, 114)`.
- BGR → RGB, формат `CHW`, значения нормализуются в `[0, 1]`.
- Тензор на вход: `(1, 3, 640, 640)`.

После инференса координаты боксов переводятся обратно в систему исходного кадра: убирается padding, координаты делятся на коэффициент `ratio`, затем обрезаются по границам изображения.

См. `preprocess_image()` в `src/inference/model_loader.py`.

## 2. Один forward pass — два выхода

`onnxruntime` один раз за кадр запускает ONNX-модель REACT++. Сессия возвращает два массива:

| Выход | Форма | Столбцы |
|-------|-------|---------|
| Боксы | `(N, 6)` | `x1, y1, x2, y2, class_id, confidence` |
| Связи | `(M, 5)` | `subject_idx, object_idx, predicate_id, triplet_score, relation_score` |

- **Боксы** — обнаруженные объекты с классами из датасета PSG (person, chair, cup и т.д.).
- **Связи** — **триплеты** *(субъект, предикат, объект)*, где `subject_idx` и `object_idx` — **индексы строк** в массиве боксов того же прохода модели.

Имена классов объектов и предикатов загружаются из метаданных ONNX (`obj_classes`, `rel_classes`) через `load_class_names()`.

На уровне архитектуры REACT++ (бэкбон YOLO12m + scene-graph head) обучен **совместно**: детекция и предсказание отношений — не отдельные этапы в Python. Модель сразу предсказывает, какие пары детекций связаны и каким предикатом (`on`, `wearing`, `holding` и т.д.).

## 3. Постобработка

Постобработка в `SceneGraphEngine.predict()`. Пороги по умолчанию — в `src/config.py`:

- `box_conf` = 0.40
- `rel_conf` = 0.05
- `max_relations` = 20

### Шаг A — фильтрация связей

1. Оставляются связи с `triplet_score >= rel_conf`.
2. Сортировка по убыванию `triplet_score`.
3. Берётся не более `max_relations` триплетов.

`triplet_score` — уверенность в **целом триплете** (субъект + предикат + объект).  
`relation_score` сохраняется в результате и JSON, но **не используется** для фильтрации.

### Шаг B — фильтрация боксов

1. Собираются индексы боксов, участвующих в оставшихся связях (субъект или объект).
2. Остаются боксы с `confidence >= box_conf`.
3. **Исключение:** бокс **всегда сохраняется**, если он участвует в оставшейся связи, даже при `confidence < box_conf`. Иначе стрелка отношения могла бы указывать на скрытый объект.

### Шаг C — перенумерация индексов

После отсечения боксов индексы в связях пересчитываются (`old_to_new`), чтобы `subject_index` / `object_index` указывали на корректные объекты в финальном списке.

## 4. Построение графа сцены

`_build_result()` собирает итоговые структуры:

- **Узлы** — по одному на каждую оставшуюся детекцию (`DetectedObject` + узел в `networkx.DiGraph`).
- **Рёбра** — направленные связи от субъекта к объекту с меткой-предикатом.

Пример: `person - on - chair` → узел `person` → ребро `on` → узел `chair`.

Граф **направленный** (`DiGraph`): «person on chair» ≠ «chair on person».

Объекты и связи можно экспортировать в JSON (`SceneGraphResult.to_json_dict()` / `save_json()`).

## 5. Пример

Допустим, модель вернула 8 боксов и 50 кандидатов связей:

```
Боксы:  [0: person 0.9] [1: chair 0.7] [2: cup 0.35] [3: table 0.2] ...
Связи:
  (0, 1, "on",      triplet_score=0.18)  — person on chair
  (0, 2, "holding", triplet_score=0.12)  — person holding cup
  (2, 3, "on",      triplet_score=0.08)  — cup on table
```

При порогах по умолчанию:

1. Все три связи проходят `rel_conf` (scores ≥ 0.05).
2. Боксы: person и chair — по confidence; cup (0.35) и table (0.20) ниже `box_conf`, но **принудительно остаются**, так как участвуют в связях.
3. Остальные боксы с низким confidence и без связей отбрасываются.

В UI рисуются боксы, стрелки между центрами боксов, подписи предикатов, информационная панель и окно мини-графа.

## 6. Сравнение с классическим двухэтапным SGG

| | Классический подход | REACT++ (этот проект) |
|--|---------------------|------------------------|
| Детекция | Отдельный детектор | Встроена в ту же модель |
| Связи | Часто O(N²) пар + relation network | Предсказаны с индексами боксов за один проход |
| Число проходов | 1 + много на пары | **1** ONNX run на кадр |
| Real-time с веб-камеры | Сложнее при многих объектах | Подходит для live-режима |

## 7. Настраиваемые пользователем параметры

| Параметр | Влияние |
|----------|---------|
| **Box Confidence** | Меньше лишних объектов без связей |
| **Relation Confidence** | Меньше слабых и ложных триплетов |
| **Max Relations** | Лимит топовых связей на кадр |

Trackbar’ы обновляют пороги в реальном времени через `SceneGraphEngine.set_thresholds()`.

## 8. Чего проект не делает

- **Нет сегментации** — только axis-aligned bounding box’ы (без масок SAM/SAM2).
- **Нет отдельной relation-модели на пары в Python** — связи приходят из одного экспорта REACT++.
- **Нет обучения** — только инференс по готовым ONNX-весам.

Подробности экспорта и инференса см. в [SGG-Benchmark](https://github.com/Maelic/SGG-Benchmark) и на карточке модели на Hugging Face.
